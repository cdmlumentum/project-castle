# v0.26.5 — FDE tables and an explicit coupling-capacity fallback

The named alternative `tabulated_width_offset_v1` replaces repeated optical
profile evaluations inside Powell with tracked local FDE tables. Select
`config/native_tabulated.json`; previous numerical methods remain available.
This implements a design method, not a new physically validated device result.

## Detuning first

The width table starts with nine widths between the fixed Block 1 endpoints,
at **1260 and 1340 nm only**. Isolated upper and lower modes use the unchanged
full production domain; lower modes are invariant and cached per wavelength.
Complex betas, identities and raw fields retain their existing cache provenance.
A rejected sample never enters a table or becomes a tracking reference.

Detuning must form one monotone width branch at each wavelength. PCHIP never
extrapolates. Independent width midpoints test complex interpolation error
against the existing coefficient absolute/relative and device-length phase
tolerances. Failed intervals refine, up to the explicit table-node limit.
Nonmonotone data require a branch diagnosis rather than interpolation across a
turn. Unreachable targets are counted; one shared physical width minimizes the
worst error at the two wavelengths. Scalar inversions are exported as design
diagnostics, then a cheap minimax fit produces fixed-endpoint monotone cubic
B-splines. No FDE calls occur inside this spline optimizer.
The supplied configuration allows 2000 cheap table objective evaluations per
spline fit; `--max-evaluations` overrides that allowance. Fresh optical work is
controlled separately by table sizes and the solve/time budgets. This is no
longer a 120-whole-profile-FDE-evaluation workload.

## Coupling versus width and signed lateral offset

Coupling depends on both width and offset. Five initial width rows and seven
signed offsets, including zero, provide 70 coefficient samples at two
wavelengths. A coefficient sample can require up to three FDE solves, with the
existing invariant/raw caches reducing that count. This is not 70 guaranteed
fresh solves. No symmetry between positive and negative offset is assumed.
The second table interpolates the **full complex coupling**, on the existing
continuous branch convention. Offset midpoints, width midpoints and joint
cell centers are independently solved and refine the two table axes when
needed. Table caps are separate from longitudinal grid caps.

With the width frozen, scalar offset inversions use signed approach/departure
branches; the final offset remains a fixed-endpoint monotone cubic spline.
Both wavelengths use the same geometry. A pointwise optimum is not necessarily
realizable by six smooth monotone spline controls; residual error is retained.

## Capacity fallback and unambiguous ratios

**Project convention:** full detuning is
`Delta_beta = beta_upper - beta_lower`, with targets
`Delta_beta_target = -D*cos(theta)` and `kappa_target = K*sin(theta)`.
The previous default is **K = D/2**, hence **D/K = 2**. In terms of half
detuning, `delta_12_max/K = 1`. This differs from `D = K/2`.

For the new method the detuning amplitude D and endpoints stay fixed. On 501
longitudinal positions along the fitted width profile, compute the common
sampled zero-offset capacity:

```
K_capacity = min over both wavelengths and sin(theta)>1e-8
             [Re(kappa(width(z), offset=0, wavelength))/sin(theta(z))]
K = min(D/2, K_capacity)
```

This preserves a smooth shared Blackman target rather than clipping it locally.
If K is reduced, report explicitly that the original amplitude relationship
does not hold, with **D/K, K/D and (D/2)/K**, and retain the full envelope.
If there is no positive valid capacity, fail rather than invent coupling.
Complex phase error and spline constraints can still prevent an exact fit.
Zero offset is used conservatively as requested; it is not asserted to be the
global coupling maximum for every geometry. The two-dimensional table and
direct validation expose residuals if that assumption is imperfect.

`block2_summary.json`, comparison JSON/CSV/plots and the schema-3 handoff carry
the selected K and ratio. Comparison errors normalize coupling by the selected
K, and Block 3/4 exports and interpolation checks retain that same scale.
The report separately includes actual sampled peak detuning/coupling and their
ratio per wavelength; those peaks need not equal the target amplitudes.
Schema 1/2 artifacts remain readable with the original D/2 target.

A smaller K reduces the modal gap. A good new target fit does **not** establish
adiabatic transfer at the existing length. Propagation and independent device
validation are still required. No automatic length change is made.

## Negative kappa squared: evidence, not unconditional clipping

The default remains strict. A small isolated-versus-coupled beta difference
does not independently establish numerical uncertainty. Existing measured
negative endpoint values are **not approved for clipping by this revision**.

`tools/check_coupling_background.py` adds an isolated diagnostic alternative
that keeps both continuous residual slabs and removes only the other ridge.
It compares the initial monotone profile's two endpoints and zero-offset
section, at the two wavelength endpoints, with the production isolated
definition and two refined meshes. It has a 60-fresh-FDE / 45-minute emergency
cap; exhaustion produces an incomplete diagnostic, never an approved bound.
The production isolated definition, Block 1 records and meshes stay unchanged.
The existing coefficient-stability tool provides complementary domain checks.
No diagnostic is launched merely by loading the new configuration.

An optional `solver.coupling_zero_evidence` JSON path enables
`zero_compatible_within_uncertainty_v1` **only** for exact reviewed cases:

* Schema 1, status `reviewed_bound`, matching `evidence_identity(config)`.
* Cases keyed by `case_id(geometry, wavelength)` from
  `vlac.coupling_uncertainty`; full SI geometry, solver/material/implementation
  identity and wavelength must match. No interpolation of uncertainty bounds.
* Each record has `raw_q_real`, `raw_q_imag`, a positive finite
  `q_absolute_error_bound`, `matched_background_checked`,
  `mesh_domain_checked` and a substantive `review_rationale`.
* The raw q must match, its uncertainty disk must include zero, and the point
  must pass the existing large-separation threshold and all mode checks.
* The conservative complex bound `sqrt(abs(q)+u_q)*device_length` must be at
  most the existing `convergence.phase_error_rad`. This whole-length bound
  deliberately avoids assuming a tiny affected z interval. It is a necessary
  small-coupling screen, not an IL/XT certificate.

Only then is operational kappa set to zero, with a distinct extraction flag.
The raw q, bound, evidence hash and provenance remain in every saved coefficient;
handoffs verify that evidence again. The measured project endpoint deficits
are too large for an automatic conclusion from their relative beta size.
Mesh sensitivity alone is not a bound on systematic background/basis error.
Field tracking overlap is not a power-normalized coupling integral.

## Execution and validation

```
python tools/check_coupling_background.py --config config/native_tabulated.json --endpoint-dir <block1> --out diagnostics/coupling_background_<new-id>
python tools/run_vlac.py block2 --config config/native_tabulated.json --endpoint-dir <block1> --out outputs/tabulated_<new-id>
```

The diagnostic may return review/incomplete. It does not authorize a long run
or manufacture an uncertainty certificate. A strict endpoint preflight still
precedes all table construction; unresolved extraction problems remain visible.

The supplied run configuration carries an eight-hour emergency cap and a
7.5-hour measured completion plan. Optional table checks/refinements stop to
reserve direct final-profile/midpoint FDE and export time. The initial tables
must still be affordable; a solver stall, invalid endpoint, or insufficient
mandatory-work budget can prevent completion. No convergence guarantee or
measured speedup is claimed without a licensed run.

The selected geometry is directly evaluated at both wavelength endpoints and
independent longitudinal midpoints. Saved coefficients and objective come from
these FDE samples, never from table interpolation. Reports distinguish table
interpolation, spline optimizer termination, longitudinal convergence, target
residual, optical mesh/domain convergence and physical validation. A direct
FDE/table disagreement prevents an optimizer-converged claim. Compatible
checkpoints retain completed samples, and raw mode caches retain each solve.

Sources: REF-002/004 in the source register support sequential design.
[SciPy PCHIP](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html)
documents shape preservation. The capacity fallback and uncertainty policy
are explicit project alternatives, not attributed to the reference papers.
