# v0.26.3: exploratory domain warnings and coefficient sensitivity

The user approved proceeding with a short exploratory pilot while keeping the
2e-5 effective-index domain tolerance unchanged. That scalar comparison alone
does not decide mode identity or the accuracy of detuning and complex coupling.

## Pilot policy

`solver.endpoint_domain_policy` defaults to `strict`. The explicitly named
`warn_exploratory` policy allows the unchanged absolute domain-index comparison
to be a recorded warning. Configuration validation restricts this policy to
the guarded native / monotone Powell alternative, no more than six objective
evaluations, no optimization-grid refinement, 120 FDE solves and 2700 seconds.
It cannot silently become a long production optimization.

Independent compact-domain endpoint modes must still agree with the Block 1
handoff at the original tolerance. The full-domain fields must match those
compact fields after coordinate alignment, with the original tracking-overlap
threshold. Selected profile endpoint fields are also checked against the
independent full-domain anchors. Detuning signs, TE eligibility, tracking
overlap and extraction validity remain mandatory. No tolerance is increased
and no imaginary coupling is discarded.

The preflight also checks the full coupled coefficients at the fixed endpoints.
Invalid endpoint extraction stops the run before Powell even under the warning
policy: changing interior controls cannot repair a fixed endpoint. This early
gate was added after the licensed pilot/study described below; it changes no
FDE physics or coefficient arithmetic.

The endpoint preflight saves field identities and scalar discrepancies separately.
Profile validation still reports a failed domain comparison; exploratory exports
are marked `review` and `exploratory_only` even when optimization and midpoint
checks succeed. Profile handoffs distinguish the warning policy from strict
production settings.

The pilot reserves time for its independent midpoint grid and exports using the
existing measured-cost planner. The solve/time caps remain emergency guards.
`tools/prepare_tracking_pilot.py` prepares the capped configuration in a new
directory and never launches a longer run automatically.

## Targeted coefficient sensitivity

`tools/check_block2_coefficient_stability.py` freezes the pilot geometry, or an
explicitly labeled initial monotone geometry if no valid candidate exists.
It checks the output and zero signed-offset section at 1260 and 1340 nm using:

1. The production numerical settings.
2. 1.25x and 1.5x transverse mesh cell counts at fixed domain.
3. 1.25x and 1.5x lateral domain widths at fixed nominal mesh spacing.

Only diagnostic settings change. Production geometry, mesh, boundaries, trial
mode count, material models, tolerances and complex-coupling conventions remain
unchanged. The check has a separate cap of 60 fresh FDE solves / 45 minutes.

Comparisons reuse the existing Block 0 scalar acceptance calculation: effective
index, loss, full complex detuning and coupling, coefficient absolute/relative
tolerances and phase-error budget. The +/- square-root gauge is aligned only
for comparison; complex values and the applied sign are retained. Both the
production-baseline differences and adjacent-setting differences are reported.
Flagged extraction values are retained for diagnosis, with invalid references
explicitly marked and never supplied to profile optimization.

These four sentinel sections do not constitute a Block 0 certificate, whole-grid
convergence, wavelength-interior validation or physical device validation. A
longer run remains gated on valid extraction, pilot midpoint checks and completed
coefficient sensitivity checks; the diagnostic does not launch one.

The numerical variations use the existing FDE domain and mesh-cell controls
described in the [official Ansys solver documentation](https://optics.ansys.com/hc/en-us/articles/360034916973-FDE-solver-Simulation-object).
The diagnostic can read checksummed pilot raw-mode packets whose complete cache
keys match, without modifying the pilot cache. Refinement solves remain separate.

## Licensed results, 2026-11-27

The exploratory pilot passed independent endpoint field identity (minimum aligned
overlap 0.9999863) and reproduced the compact Block 1 indices to numerical
precision. The scalar domain discrepancies were retained as warnings. The first
candidate was rejected at z=1031.25 um, 1260 nm, for negative kappa squared with
minimum tracking overlap 0.94836. The pilot was intentionally discontinued after
the fixed-output issue was confirmed from checksummed original raw packets;
39 FDE calls were confirmed complete, and an in-progress candidate was discarded.
No valid optimizer candidate or midpoint-validation result was published.

The separate sensitivity study completed all 20 sentinel/settings combinations
in 2241.422 s (37 min 21 s), with 46 fresh FDE solves, zero failed solves, and four
exact-key pilot-cache packet reuses. Its geometry is explicitly the initial
monotone profile, not an optimized device. All cross-setting field identity
overlaps exceeded 0.9998097.

- All ten output extractions had negative kappa squared. At 1260 nm, output
  kappa was approximately +945i, +936i and +928i rad/m across the three mesh
  levels. At 1340 nm it was approximately -1537i, -1517i and -1509i rad/m.
- The wider-domain cases reproduced production-baseline coefficients closely:
  maximum delta-beta change 1.17e-6 rad/m and full complex-kappa change 1.82e-7
  rad/m. The metric-only lateral-domain comparisons passed at these sentinels;
  flagged output extraction still prevents overall acceptance.
- Mesh refinement did not pass the existing numerical criteria. Changes relative
  to production settings reached 500.69 rad/m in detuning, 52.43 rad/m in full
  complex coupling and 1.017e-3 in individual effective indices. These are sampled
  differences, not certified error bounds or whole-profile convergence estimates.
- At the outputs, the coupled-supermode splitting is smaller than the isolated-
  guide detuning. Consequently the current squared-coupling formula is negative.
  Boundary expansion did not remove this discrepancy. Its physical/model origin
  is not established by these checks.

See `diagnostics/block2_coefficient_stability_20261127/` for the source-identified
raw report, CSV, inspected plot, pilot assessment and derived findings. Execution
completed, but coefficient validity and numerical convergence did not pass.
No longer optimization or physical device validation was started. The fixed-end
coefficient preflight was added afterward and verified with focused synthetic
regressions so future pilots fail before Powell for this condition.
