# v0.26.4: sequential width and lateral-offset fitting

`sequential_width_offset_v1` is a named Python orchestration alternative using
the native MODE/FDE backend and guarded translation-aware tracking. Select it
with `config/native_sequential.json`. Existing joint Powell configurations and
standalone LSF coordinate-pattern optimizations retain their numerical methods.

## Design basis and implementation

D'heer et al., *Nonvolatile Liquid Controlled Adiabatic Silicon Photonics
Switch*, JLT 35, 2948–2954 (2017), section II, equations (3)–(7), prescribe the
width profile from detuning and then the gap from coupling. Their equations also
describe the splitting-based coupling extraction and identify a more exact
mode-profile-based alternative. The vertical adaptation is described in D'heer
et al., *Vertical liquid controlled adiabatic waveguide coupler*, OE 26,
19877–19884 (2018), section 2: one width remains fixed, while the other width
and center-to-center separation vary. See REF-002 and REF-004 in the
[source register](../references/source-register.md).

Our target remains `-D*cos(theta)` for upper-minus-lower detuning and
`(D/2)*sin(theta)` for coupling. This preserves the current negative-to-positive
endpoint direction. The signed lateral offset varies; vertical spacing and
lower-guide width stay fixed.

For each optimization grid:

1. Run the existing independent endpoint mode/complex-coefficient preflight.
   A fixed endpoint with negative kappa squared still stops the run before fits.
2. Fit only the upper-width spline against the worst normalized real detuning
   error across all fitting z/wavelength samples. Use isolated modes on the
   full production domain with the upper guide centered at x=0; no compact
   domain or coupled-supermode solve is substituted into this width objective.
   Track the upper mode along z and between wavelengths, bound midpoint
   recovery, reject bad fields/overlaps, and match endpoint fields to the
   independently verified full-domain anchors. Solve the invariant lower mode
   once per wavelength in each candidate; the native raw cache handles reuse.
3. Freeze the accepted width controls. Fit only the signed offset spline
   against the worst full-complex coupling residual. Use the unchanged native
   full-domain coefficient extraction and guarded tracking. No absolute-value
   replacement of complex kappa, clipping of kappa squared, or accuracy change
   is made.
4. Recompute the published objective from BOTH detuning and full-complex
   coupling residuals on the actual final coupled geometry. Centered isolated
   detuning need not exactly equal detuning from translated sampled geometries;
   that discrepancy remains visible in the final comparison artifacts.
5. Evaluate fresh longitudinal (z) midpoint cross-sections at the two
   configured endpoint wavelengths only, reusing exact matching raw solves.
   Require this z interpolation check for `grid_converged`; refine only z within
   the existing sample/refinement limits. No interior wavelength is checked.
   These checks do not establish transverse mesh/domain convergence.

Each stage uses bounded Powell over `control_points-2` monotone stick-breaking
coordinates. These are two separate one-dimensional longitudinal PROFILE fits,
not two scalar root solves. This implementation retains clamped cubic splines,
fixed endpoints, smoothness and optional slope/curvature constraints; it does
not assume that a pointwise inverse at each wavelength gives a mutually
compatible smooth geometry. It performs one width pass and one offset pass per
grid; no automatic joint refinement is performed.

The width-stage report contains normalized/maximum/RMS detuning residuals by
wavelength, sampled detuning monotonicity, and endpoint target-range diagnostics.
Range diagnostics are not proofs of continuous invertibility. No target-fit
acceptance threshold is invented: optimizer termination alone does not mean
that either prescribed target is reachable with the fixed endpoints/stack.

## Budgets, resume and outputs

`max_function_evaluations_per_grid` is shared, not doubled: floor(N/2) width
evaluations and the remaining offset evaluations. A minimum of two is required.
The existing solve/time limits include preflight and midpoint validation as well
as optimization. The measured-cost completion planner conservatively reserves
three times the observed isolated-grid cost until coupled costs are available,
plus longitudinal midpoint validation and export time. Estimates cannot guarantee completion
through a license loss or solver stall; hard limits remain emergency guards.

Checkpoints record the completed width pass and fitting wavelength grid. A
resume reuses that width pass and restarts offset Powell directions; an
interrupted width pass restarts from its previous completed grid. This is a warm
restart, not exact SciPy optimizer continuation. Workflow provenance includes
the new module; handoff signatures distinguish this alternative from joint
Powell, and import validates monotone controls for both splines.

Existing geometry and target-comparison JSON/CSV/PNG/PDF exports are retained.
`optimizer_history.json` and `block2_summary.json` expose the width-stage report,
offset objective/termination, combined objective, and independent grid flags.
Overall optimization convergence requires both stage termination flags.

Example invocation from this checkout, after choosing a compatible endpoint
artifact and an explicit solve/time budget:

```powershell
python tools/run_vlac.py block2 --config config/native_sequential.json --endpoint-dir outputs/endpoint --out outputs/sequential_trial --max-evaluations 6 --max-refinements 0 --max-solves 120 --max-seconds 2700
```

The example is a bounded trial and is not expected to establish optimization
convergence with three evaluations per stage. `warn_exploratory` remains an
explicit optional pilot policy with the original <=6 total evaluations,
no optimization refinements, <=120 solves and <=2700 seconds restrictions.
The supplied configuration is strict. Neither policy bypasses invalid complex
coefficient extraction. Standalone `native prepare` rejects this alternative;
use the Python launcher with the native backend.

`tools/prepare_tracking_pilot.py` now defaults to the sequential method when
preparing a new pilot configuration; `--method monotone_powell` selects the
previous joint alternative explicitly. The tool only prepares files and does
not launch MODE. Existing pilot files and results are not rewritten.

## Endpoint-wavelength-only execution for Blocks 2 and 3

At the user's request, all Block 2 and Block 3 execution paths use exactly
`wavelength_min_m` and `wavelength_max_m` (currently 1260/1340 nm). Both keep
independent z-midpoint checks and the existing numerical tolerances. Neither
runs wavelength midpoints or claims interior-wavelength accuracy.

Block 3's optional retained characterization also stays at those two wavelengths
and refines only z, using the named `direct_nested_z_band_edges_v1` method.
This applies even when `characterization.enabled` or `--characterize` is set;
that CLI command is a Block 3 execution path. The separate Python library
characterization function retains its explicitly requested broadband option.
Endpoint-only datasets have a distinct method/checkpoint identity and are
validated as exactly two matching wavelengths. Existing saved broadband data
remain readable for offline inspection/Block 4, but Block 3 rejects a
non-endpoint upstream profile before evaluating it.

Standalone native Block 3 similarly disables wavelength-midpoint checks and
rejects a profile grid containing other wavelengths. MODE license preflight
uses the minimum wavelength. Automatic selected-design comparisons against a
Block 0 certificate, when invoked from Blocks 2/3, also use only the endpoints
and record this scope in their report/cache identity. Standalone Block 0
calibration/verification studies retain their independently requested coverage.
No mesh, domain, tracking threshold or coefficient tolerance is relaxed.

## Verification scope

Offline tests use explicitly synthetic optical data to check stage isolation,
detuning-fit improvement, fixed monotone endpoints, full-complex residuals,
combined budget accounting, endpoint-only sampling, endpoint/candidate gates,
checkpoint resume and method identity. They do not establish a licensed MODE
speedup, optical convergence or physical device performance. No production
simulation is launched as part of this implementation. The previously observed
weak-coupling extraction inconsistency is not repaired by changing optimization
order and remains a blocker for that geometry under the mandatory preflight.
